# Nota Hayati

A simple Indonesian invoice app for Hayati Cake & Bakery. Built for a shop owner who wants to enter an item, quantity, and unit price, then save or print a stamped delivery note.

## For Ibu

1. Open **Nota Hayati** and tap **Buat Nota Baru**.
2. Enter the item name, quantity, and price. Tap **Tambah Barang** for more items.
3. Tap **Simpan & Lihat Nota**. The invoice number, date, total, and shop stamp are automatic.
4. Tap **Cetak Nota** to choose a printer, or **PDF / Bagikan** to save or share the PDF.
5. For a batch, open **Cetak**, choose a start and end date, then print or export all invoices. Both dates are included. Optional branch filtering and half-month shortcuts are available.

The app works without an account and the Android app is offline from its first launch. Invoices are stored on the main phone. Export a backup from **Pengaturan** regularly and before uninstalling, clearing app data, or changing phones. Import it on the replacement phone. Automatic cross-device sync is intentionally absent.

## Installation

**Android is the recommended primary phone for this version.** The signed APK is a complete app with all assets bundled. Download and open the APK, then tap **Install**. Android may request permission to install from the download source; a family member should handle that initial setup. No coding, server, login, or shop configuration is needed to start making invoices. The shop address and phone are already filled in. A Play Store listing is a separate publishing step requiring a developer account. Store or device policies may impose additional checks.

The same code also builds a home-screen web app for iPhone and Android. Once hosted with HTTPS, open it in Safari on iPhone and use **Share > Add to Home Screen**, or use **Install app** in Chrome on Android. The first web visit must be online to cache the app. Browser storage and native Android storage are separate; use backup export/import to transfer them.

## Invoice requirements and source fidelity

The source letter is _Konsinyasi - Surat Pemberitahuan Kelengkapan Dokumen Penagihan_, dated 31 July 2026. Section 2, pages 2-3, allows supplier invoices generated by a system, asks for one delivery note per consignment, and asks for both parties' names and signatures. The app includes a supplier-issued delivery note with:

- Unique number and delivery date, recipient and optional branch.
- Quantity, item name, unit price, line subtotal, and total Rupiah.
- Hayati shop details and the shop stamp.
- Recipient and supplier name lines and space for handwritten signatures.

The design follows the blank Hayati invoice supplied in the conversation. Address transcribed from that form: **Jl. Ki Hajar Dewantoro No. 71 (Depan Pintu Gerbang Belakang UNS), Solo**. Phone uses **081326203778**, as explicitly requested, instead of the older number on the blank form. These details are editable. The supplier display defaults to the business name; the parties can fill their personal names on paper. Destination details can be changed under **Ubah Detail**.

The printed stamp is not a signature, a receipt, or a tax duty stamp. Handwritten signatures still need to be collected. KOKARMINA's receipt, acceptance/return memos, and billing recap are separate documents and are outside this invoice app. The total shown is consigned goods value, not net payment after returns.

Invoice snapshots retain their original shop details when Settings changes. Editing an invoice retains its number. Deleted numbers are not reused. Backup import validates all records before merging, skips identical invoices, and rejects conflicts without overwriting local data. Currency calculations round each quantity-times-price line to a whole Rupiah.

## Development

Requires Node.js 24.

```bash
npm ci
npm run dev
npm test
npm run build
npm run preview
```

Production assets are in `dist/`. The app has no backend, analytics, external fonts, or cloud database. PWA assets use relative paths, allowing hosting at `/moms-note/`.

## Android

The native wrapper uses Capacitor 8, Android API 24+, Java 21, and SDK 36. Native PDF and backup exports use the Android share sheet. Printing uses the Android print service, renders selected PDF pages at up to 200 DPI, and respects page selections and cancellation. Printer availability depends on the phone's print service and printer. Generated PDFs retain their vector text.

```bash
npm run build
npx cap sync android
cd android
./gradlew assembleRelease bundleRelease lintRelease
```

**Build and Check** runs web tests and Android builds on GitHub. Its Android artifact includes the unsigned APK and app bundle. A release APK must be signed before installing. Keep the signing keystore and password private and backed up; the same key is needed for updates. Never commit signing keys or personal invoice backups. Increase `versionCode` for every Android update.

The **Publish Web App (Manual)** workflow is ready for GitHub Pages. To use it, select GitHub Actions as the Pages source, then run that workflow. It never publishes automatically on a code push.

## Stamp asset

`public/hayati-stamp.png` is a transparent derivative of the supplied stamp photo, cleaned with the built-in image tool. Final prompt: extract only the existing blue stamp, rotate the text upright, remove paper and pencil marks, preserve the cupcake, lettering, and exact text `Hayati`, `CAKE AND BAKERY`, `081326203778`; do not invent signatures or redesign the stamp. Settings allows replacing it with a PNG, JPEG, or WebP up to 1.2 MB. No original photos or source letter are committed.

## Verification

`npm test` covers arithmetic, date validity, inclusive ranges, half-month boundaries including leap years, branch filtering, backup round trips, duplicate rejection, and conflict-safe import. Browser checks cover invoice creation and editing, persistence after reload, individual and bulk PDF export, settings, and phone layouts. Physical phone and printer behavior should be checked before relying on a production billing run.
